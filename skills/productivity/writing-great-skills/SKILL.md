一个技能的存在是为了从随机系统中争取确定性。**可预测性**（Predictability）—— agent 每次运行采取相同的*过程*，而不是产生相同的输出 —— 是根本美德；下面的每个杠杆都服务于它。

**粗体术语**在 [`GLOSSARY.md`](GLOSSARY.md) 中定义；在那里查找完整含义。

## 调用

两种选择，交换不同的成本：

- **模型调用**（model-invoked）技能保留**描述**（description），因此 agent 可以自主触发它*且*其他技能可以访问它（你仍然可以手动输入它的名字）。它贡献**上下文负载**（context load）—— 描述在每一轮的窗口中。机制：省略 `disable-model-invocation`，并编写一个面向模型的描述，带有丰富的触发措辞（"当用户想要……、提到……时使用"）。
- **用户调用**（user-invoked）技能从 agent 的触及范围中剥离描述：只有你，输入它的名字，才能调用它 —— 没有其他技能可以。零上下文负载，但它花费**认知负载**（cognitive load）：*你*是必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 变为面向人类 —— 一行摘要，触发列表被剥离。

仅当 agent 必须自己访问该技能，或其他技能必须访问时才选择模型调用。如果它只通过手动触发，使其成为用户调用并支付零上下文负载。

当用户调用的技能超过你能记住的数量时，堆积的认知负载由**路由技能**（router skill）治愈：一个用户调用技能，命名其他技能以及何时访问每个。

## 编写描述

模型调用的**描述**做两件事 —— 陈述技能是什么，并列出应触发它的**分支**（branches）。每个词都增加**上下文负载**，因此描述比正文更需要修剪：

- **前置技能的主导词** —— 描述是它做调用工作的地方。
- **每个分支一个触发器。** 重命名单个分支的同义词是**重复**（duplication）—— "使用 TDD 构建功能……要求测试先行开发"是一个分支写了两次。合并它们；只保留真正不同的分支。
- **削减已在正文中的身份。** 保持描述为触发器，加上任何"当其他技能需要……"的访问子句。

## 信息层次

一个技能由两种内容类型构建 —— **步骤**（steps）和**参考**（reference）—— 自由混合：一个技能可以全是步骤、全是参考，或两者兼有。核心决策是使用哪种以及每种在**信息层次**（information hierarchy）上的位置，这是一个按 agent 需要材料的紧迫程度排列的阶梯：

1. **技能内步骤** — `SKILL.md` 中的有序动作，主要层级：agent 做什么，按顺序。每个步骤以**完成标准**（completion criterion）结束，即告诉 agent 工作完成的条件。使其*可检查*（agent 能区分完成和未完成吗？）并且，在重要时，*穷尽*（"每个修改的模型都已说明"，而不是"产生变更列表"）—— 模糊的标准会引发**过早完成**（premature completion）。
2. **技能内参考** — `SKILL.md` 中的定义、规则或事实，按需查阅。通常是一个合法的扁平对等集（审查的每个规则在同一级）—— 一种好的安排，不是坏味道。*此技能全是参考。*
3. **外部参考** — 从 `SKILL.md` 中推出到单独文件的参考，由**上下文指针**（context pointer）到达，仅在指针触发时加载。（跨度从*已披露*参考 —— 一个同级文件如 `GLOSSARY.md`，仍是技能的一部分 —— 到完全的**外部参考**，存在于技能系统之外，任何技能都可以指向。）

一个要求高的完成标准驱动彻底的**跑腿工作**（legwork）—— agent 在工作中的挖掘 —— 无论技能是否有步骤，因为"每条规则已应用"约束扁平参考，就像"每个步骤完成"约束序列一样。

推得太少，顶层膨胀；推得太多，你隐藏了 agent 实际需要的材料。那种张力就是整个决策。

**渐进披露**（Progressive disclosure）是沿着阶梯向下移动 —— 从 `SKILL.md` 到链接文件 —— 这样顶层保持可读。机制：技能文件夹中的链接 `.md` 文件，以它所持有的内容命名（此技能将其完整定义披露到 `GLOSSARY.md`）。某些技能以不止一种方式使用，每种不同的方式是**分支**（branch）—— 不同运行走技能中的不同路径。分支是最干净的披露测试：内联每个分支需要的，并将只有某些分支访问的内容推到指针后面。**上下文指针**的*措辞*，而不是其目标，决定 agent 何时以及多可靠地到达材料。

在阶梯决定某物*多远*的地方，**共置**（co-location）决定*什么在旁边*：将概念的定义、规则和注意事项保持在一个标题下而不是分散，这样阅读一部分会带来它的邻居。

## 何时拆分

**粒度**（Granularity）是你划分技能的精细程度，每次切割花费两种负载之一，因此仅当切割值得时才拆分。两种切割：

- **按调用** — 当你有一个独特的**主导词**（leading word）应独立触发它，或其他技能必须访问它时，拆分为**模型调用**技能。你为新的始终加载的**描述**支付**上下文负载**，所以那种独立访问必须值得。
- **按序列** — 当仍然在前方的步骤（一个步骤的**完成后步骤**）诱使 agent 急于完成前面的步骤（**过早完成**）时，拆分一串**步骤**。将它们保持在视野之外鼓励 agent 在当前任务上做更多**跑腿工作**。

## 修剪

保持每个含义在**单一真相来源**（single source of truth）中：一个权威的地方，这样改变行为是一处编辑。

检查每一行的**相关性**（relevance）：它仍然与技能做的事情相关吗？

然后逐句，而不仅仅是逐行地捕猎**无操作**（no-ops）：对每个句子单独运行无操作测试，当一个失败时，删除整个句子而不是从中修剪词语。要激进 —— 大多数未能通过的散文应该被删除，而不是重写。

## 主导词

**主导词**（leading word）是一个已存在于模型预训练中的紧凑概念，agent 在运行技能时用它来思考（例如 *lesson*、*fog of war*、*tracer bullets*）。在整个文本中重复（虽然不一定 —— 一个强主导词可能只需要一次），它积累分布式定义，并通过招募模型已有的先验，以最少的 token 锚定一整片行为。

它两次服务于可预测性。在正文中它锚定*执行*：agent 每次该词出现时都使用相同的行为。在描述中它锚定*调用*：当同一个词存在于你的提示、文档和代码中时，agent 将那种共享语言与技能联系起来，更可靠地触发它。

寻找将技能重构为使用主导词的机会。在三个地方拼写出来的三元组（**重复**），花一个句子来指向一个想法的描述 —— 每段都是恳求**坍缩**（collapse）为单个 token 的段落。示例包括：

- "fast, deterministic, low-overhead" -> *tight* — 在一个阶段中重述的一个品质 —— 坍缩为单个预训练词（一个*tight*循环）。
- "a loop you believe in" -> *red* — 将模糊的门控转化为二进制可观察状态（循环在 bug 上变*红*，或不变）。

你双重获胜：更少的 token，*且* agent 挂靠其思考的更锋利钩子。假设每个技能都携带着主导词可以退休的重述 —— 去寻找它们。

## 失败模式

使用这些来诊断用户可能对技能遇到的问题。

- **过早完成** — 在步骤真正完成之前结束它，注意力滑向*已完成*。防御，按顺序：首先打磨完成标准（便宜，局部）；仅当它不可减少地模糊*且*你观察到匆忙时，通过拆分隐藏完成后步骤（序列切割）。
- **重复** — 相同含义在不止一个地方。花费维护和 token，并膨胀含义在阶梯上的突出程度超过其实际排名。
- **沉积**（Sediment）— 因为添加感觉安全而移除感觉有风险而沉淀的陈腐层。任何没有修剪纪律的技能的默认命运。
- **膨胀**（Sprawl）— 一个技能实在太长，即使每一行都是活的且唯一的。损害可读性和可维护性并浪费 token。治愈方法是阶梯：在指针后面披露**参考**，并按**分支**或序列拆分，这样每条路径只携带它需要的内容。
- **无操作**（No-op）— 模型默认已遵守的行，所以你支付负载什么都没说。测试：它是否改变了行为相对于默认？一个弱主导词（*be thorough* 当 agent 已经大致彻底时）是无操作；修复是更强的词（*relentless*），而不是不同的技术。
