一个模糊的想法出现了——对单次 agent 会话来说太大了，而且笼罩在迷雾中：从这里到**目的地**的路径尚不可见。Wayfinding 是关于找到那条路，而不是直接冲向目的地。这个 skill 在仓库的 issue 跟踪器上以**共享地图**的形式绘制路径，然后逐一处理它的**决策票据**——这些票据的结论是一个决策，而非待执行的构建切片——直到路线变得清晰。

目的地因每次任务而异，命名目的地是绘制地图的第一步——它塑造每一张票据。它可能是一份要移交和迭代的 spec，一个在规划开始前要锁定的决策，或者一个就地执行的变更（如数据结构迁移）。地图是领域无关的——工程工作、课程内容，凡是符合这种形状的都可以。

## 规划，不执行

Wayfinder 默认是**规划**：每张票据解决一个决策，当地图完成后路径清晰——在有人去实际执行之前没有剩余的决策要做。那种"干脆直接开干"的冲动通常就是你已经到达地图边缘、该移交的信号。一次任务可以通过**备注**覆盖这个默认行为——将执行纳入地图本身——但除非如此，产出的是决策，不是交付物。

## 按名称引用

每个地图和票据都是一个 issue，所以它有一个**名称**——它的标题。在人类阅读的所有内容中——叙述、地图的"截至目前决策"——按那个名称引用它，永远不要用裸 id、编号或 slug。一堵 `#42, #43, #44` 的墙是无法阅读的；名称一眼就能看懂。id 和 URL 不会消失——一个名称包裹着它的链接——但它们藏在名称*内部*，永远不替代它。

## 地图

地图是这个仓库的 issue 跟踪器上的一个 issue，标记为 `wayfinder:map`——规范产物。它的票据是地图的子 issue。

地图是一个**索引**，不是存储。它列出已做出的决策，并指向保存其细节的票据；每个决策只存在于一个地方——它的票据——所以地图从不复述它，只做摘要和链接。

**地图、它的子票据、阻塞关系和前沿查询在物理上如何存放是跟踪器特定的。** issue 跟踪器应该已经提供给你了——如果没有，运行 `/setup-matt-pocock-skills`。查阅跟踪器文档的"Wayfinding 操作"部分，了解*这个*仓库如何表达它们。如果没有提供跟踪器，默认使用本地 markdown 跟踪器。

### 地图正文

整个地图的低分辨率视图，每个会话加载一次。未关闭的票据**不**列在这里——它们是未关闭的子 issue，通过查询来找到。

### 票据

每张票据是地图的一个**子 issue**；跟踪器的 issue id 是它的身份。其正文是问题，大小适合一个 100K token 的 agent 会话：

```markdown
## 问题

<这张票据要解决的决策或调查>
```

每张票据携带一个 `wayfinder:<类型>` 标签——`research`、`prototype`、`grilling`、`task` 之一（参见[票据类型](#票据类型)）。

会话**认领**一张票据，在开始任何工作**之前**将其分配给驱动地图的开发者，这样并发会话就会跳过它。那个分配人*就是*认领：一张未关闭、未分配的票据就是未认领的。

阻塞使用跟踪器的**原生**依赖关系——这一点至关重要，因为它会在跟踪器自身的 UI 中*可视化*地呈现前沿，让人类无需打开地图就能看到哪些票据可以接。只有缺乏原生阻塞的跟踪器才回退到正文约定。当阻塞它的所有票据都关闭时，一张票据是**未阻塞**的；**前沿**是未关闭、未阻塞、未认领的子票据——已知区域的边缘。

答案不是正文的一部分——它在解决时记录（参见[遍历地图](#遍历地图)）。解决票据时创建的产物从 issue 链接，而不是粘贴进去。

## 票据类型

每张票据要么是 **HITL**——人类在环（Human In The Loop），与一个代表自己发言的人类*一起*工作——要么是 **AFK**，由 agent 独自驱动。一张 HITL 票据只有通过那次实时交流才能解决；agent 永远不替人类发言（一个自己回答自己问题的 grilling agent 已经破坏了这一点）。

- **Research**（AFK）：阅读文档、第三方 API 或本地资源（如知识库）以揭示一个决策所依赖的事实。由 `/research` **子 agent** 解决。当需要当前工作目录之外的知识时使用。
- **Prototype**（HITL）：通过制作一个廉价、粗糙、具体的产物来提升讨论的保真度——一个大纲、一个粗略尝试、一个桩，或通过 /prototype skill 生成的 UI/逻辑代码。将原型作为产物链接。当"它应该是什么样子"或"它应该如何行为"是关键问题时使用。
- **Grilling**（HITL）：通过 /grilling 和 /domain-modeling skills 进行交流，一次一个问题。默认情况。
- **Task**（HITL 或 AFK）：在做出*决策*之前必须完成的手动工作——没有什么要决策、原型或研究的，但讨论被它阻塞直到完成。注册某项服务以便评判其 API、配置访问权限、移动数据以便看到其形状。这是唯一*执行*而非决策的类型——它之所以有资格存在，是因为它解除了决策的阻塞，而不是因为它交付了目的地。agent 在可以独自完成的情况下驱动它（AFK）；否则交给人类一份精确的清单（HITL）。当工作完成时解决；答案记录做了什么以及任何后续票据依赖的结果事实（凭证位置、新 URL、行数）。

## 战争迷雾

地图是*刻意*不完整的：不要绘制你还看不到的东西。活跃票据之外是**战争迷雾**——你对那些你能感觉到即将到来但还无法确定的决策和调查的模糊视野，因为它们依赖于尚未解答的问题。解决一张票据会清除它前方的迷雾，将现在可以细化的任何内容升级为新的票据——一次一个，直到通往目的地的路径清晰且没有剩余票据。

地图的**尚未细化**部分记录那些模糊视野：被怀疑的问题，稍后重访的区域。它是朝向目的地的未被发现的前沿——这里的所有东西都在范围内，只是不够清晰到可以变为票据。按视野允许的程度写，粗略或完整都可以；它同时作为协作者阅读任务方向的指路牌。

**迷雾还是票据？** 测试标准是你现在能否精确地陈述问题——*不是*你现在能否回答它。

- **票据当**问题已经清晰——即使它被阻塞，你还不能处理它。
- **尚未细化当**你还无法那么清晰地表述它。不要预先将迷雾切成票据大小的碎片：它比票据更粗糙，前进一次可能升级为多张票据，或者根本没有，一旦前沿到达它时。

**尚未细化**排除已经决策的（截至目前决策）、已经是活跃票据的，以及范围外的（下一节）。

## 范围外

迷雾只朝目的地方向聚集。目的地确定了范围，所以超出范围的工作是**范围外**——它不是迷雾，不属于**尚未细化**。它在地图上有自己的**范围外**部分：你明确排除在*这次*任务之外的工作。决定它的是范围，不是清晰度，落在这里。

范围外的工作永不升级——前沿停在目的地——所以它只在目的地重新绘制时返回，且那时作为一个全新的任务，不是继续。

将某物划为范围外是一个确定范围的行为，不是路线上的步骤。当一张已存在的票据被发现位于目的地之外时——绘制时范围放错了，或者被一个结论暴露出来——**关闭它**（已关闭的票据明确不在前沿上），并在**范围外**部分留一行：摘要加上为什么范围外的原因，链接到已关闭的票据。它保持不在**截至目前决策**中——那只记录实际走过的路线——范围边界不是其上的一步。

## 调用

两种模式。无论哪种，**每个会话永远不要解决超过一张票据**——research 票据例外。

### 绘制地图

用户携带一个模糊想法调用。

1. **命名目的地。** 运行一次 `/grilling` 和 `/domain-modeling` 会话来确定这张地图正在寻找通往的终点——spec、决策或变更。目的地确定范围，所以先确定它。
2. **绘制前沿。** 再次 grilling，这次**广度优先**：在整个空间展开而非深入任何一条线索，浮现出开放的决策和现在可以迈出的第一步。**如果这浮现不出任何迷雾**——通往目的地的路径已经清晰，整个旅程小到一次会话就能完成——你不需要地图。停下来，询问用户希望如何继续。
3. **创建地图**（标签 `wayfinder:map`）：目的地和备注填好，"截至目前决策"为空，迷雾草绘在**尚未细化**中。
4. **创建你现在可以细化的票据**作为地图的子 issue——然后**第二轮**连线阻塞边（issue 需要 id 才能相互引用）。连线将它们分为前沿和被阻塞的；所有你还无法细化的留在迷雾中——**尚未细化**部分。
5. **启动 research 子 agent。** 对于你刚创建的每张 `research` 票据，启动一个 `/research` 子 agent 并行解决它，将其发现捕获在一次性 `research/<名称>` 分支上，并从票据中放置上下文指针。
6. 停止——绘制是一次会话的工作；它不手动解决任何东西。

### 遍历地图

用户携带一个地图（URL 或编号）调用。票据是**可选的**——没有的话，你选择下一个决策，不是用户。

1. 加载**地图**——低分辨率视图，而非每张票据的正文。
2. 选择票据。如果用户指定了一张，用它。否则按顺序取第一张前沿票据。**认领它**：在任何工作之前将它分配给自己。
3. 解决它——**按需放大**：按需获取任何相关或已关闭票据的完整正文；调用 `## 备注` 块中命名的 skills。如果不确定，使用 `/grilling` 和 `/domain-modeling`。
4. 记录结论：将答案作为**结论评论**发布，**关闭** issue，并在地图的"截至目前决策"中**追加一个上下文指针**。
5. 添加新浮现的票据（先创建后连线）；将答案使其变得可细化的任何迷雾升级，从**尚未细化**中清除每个已升级的条目，使它们只存在于新票据中。如果答案揭示某张票据——这张或另一张——位于目的地之外，**将其划为范围外**而不是在路线上解决它。如果该决策使地图的其他部分失效，更新或删除那些票据。

用户可能并行运行未阻塞的票据，所以预期其他会话同时在编辑跟踪器。
