# Wizard

**向导**（wizard）是一个 bash 脚本，逐步引导人类完成手动流程 —— 那些手工做很繁琐、每次重新向 AI 解释也很繁琐的流程。它打开每个 URL，确切地说点击什么和复制什么，捕获值，将它们写入应去的地方（`.env`、GitHub secrets），在每个阶段确认，并显示还有多少剩余。它可能配置第三方服务、运行一次性迁移，或将项目从一种状态移动到另一种状态。

令人愉快的 UX 已由 [template.sh](template.sh) 解决 —— 带剩余时间的进度、确认门控、跨平台 URL 打开（包括 WSL）、隐藏的 secret 输入、幂等的 `.env` upserts、`gh secret`/`gh variable` 写入，以及关闭摘要。**你的工作仅是划定流程的范围并编写其阶段。** `STAGES` 标记上方的库在每个向导中完全相同；那种一致性是重点 —— 永远不要手动编辑它。

向导默认是临时的 —— 为一次运行构建，保存到临时或 `scripts/` 路径，在作业完成时删除。仅在用户想要一个应存在于仓库中的可重复设置路径时才提交它。

## 流程

### 1. 划定流程范围

计算出人类必须采取的每个手动步骤以及在此过程中捕获的每个值。先阅读仓库 —— 不要冷问：

- 对于设置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用是向导必须产生的值）。
- 对于迁移或转换：当前状态、目标状态以及它们之间的不可逆操作。

然后向用户显示有序的阶段列表和每个产生的值，并确认 —— 他们可能添加、删除或重新排序。

**完成时：** 每个阶段按顺序命名，对于每个捕获的值你知道 (a) 人类从哪里获取它，(b) 它写到哪里（`.env`、GitHub secret、两者都写，或不写 —— 某些阶段是纯操作），以及 (c) 它是 secret（隐藏输入）还是公开的。

### 2. 映射每个阶段的旅程

对于每个阶段，编写人类遵循的精确路径：打开哪个 URL，在那里做什么，值在哪里显示，它填充哪个变量 —— 例如 "Dashboard → Developers → API keys → Reveal test key → copy"。在你不实际知道当前 UI 或确切命令的地方，说出来并询问用户或检查文档 —— 永远不要发明可能不存在的步骤。

**完成时：** 每个阶段追踪到陌生人可以遵循的具体指令。

### 3. 编写向导

将 `template.sh` 复制到目标路径。用每个步骤一个 `stage` 替换示例阶段，按依赖顺序。使用库辅助函数 —— `stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm` —— 并将 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设置为诚实的估计（这驱动剩余时间显示）。

保持模板设定的标准：在请求值之前打开 URL，对任何秘密使用 `ask_secret`，`write_env` 每个持久化值，`set_secret` 仅 CI 实际需要的值，在任何不可逆操作之前 `confirm`。每个 `stage` 清屏，这样只有当前步骤可见 —— 保持一个阶段为一个聚焦的任务，这样人类需要的内容不会滚动消失。不要触摸标记上方的库。

### 4. 验证并交接

- `bash -n <script>`；如果可用则运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端到端运行它 —— 它打开浏览器并阻塞在人类输入上。改为静态追踪它：第 1 步的每个值被捕获并落在第 1 步说的地方，每个 `set_secret` 名称完全匹配 CI 中的 `secrets.*` 引用。
- 告诉用户如何运行它。如果它是可重复的设置路径，提交它并从 README 链接到它，这样下一个人运行脚本而不是询问 AI。
