## 它做什么

`writing-great-skills` 是你编写和编辑 skills 时要对照的参考——使 skill 可预测的共享词汇和原则。

一个 skill 的工作是从随机系统中争取确定性，因此目标不是每次运行都相同的*输出*，而是相同的*过程*。**可预测性**是根本美德，每个设计选择都以此为评判——而不是根据 skill 读起来有多聪明、多完整或多详尽。

## 何时使用它

你通过输入 `/writing-great-skills` 来调用它——agent 不会自行调用它。

每当你在创作新 skill 或编辑现有 skill 并希望它每次都以相同方式行为时使用它：决定调用模式、写描述、选择什么放在 `SKILL.md` 中 vs 链接文件，或诊断为什么一个 skill 行为异常。

## 认知负荷

整个参考所围绕的概念是**认知负荷**——以及其对应物，**上下文负荷**。每个 skill 消耗其中之一：

- **模型调用**的 skill 每轮在窗口中保留描述，因此它消耗**上下文负荷**但会自动触发。
- **用户调用**的 skill 剥离该描述；它消耗零上下文负荷，但现在*你*是必须记住它存在的索引——那就是**认知负荷**。

这些 skills 中的大多数是用户调用的，这就是为什么认知负荷是整个系统被构建来管理的压力：当用户调用的 skills 多到超出你能在脑中持有的范围时，解决方案是一个**路由器 skill**，它命名其他 skills 以及何时使用每个。一旦你开始用这两种负荷思考，大多数创作决策——拆分或不拆分、内联或披露、模型调用或用户调用——就变成了在不同地方做的相同权衡。

## 其他杠杆

参考的其余部分是善用这些负荷的工具箱：

- **引导词**——一个已经存在于模型预训练中的紧凑概念（*tight*、*red*、*tracer bullet*），agent 在运行 skill 时用它来思考。它以最少的 token 锚定执行*和*调用；寻找一个词就能消除的重述。
- **信息层次**——从 skill 内步骤，到 skill 内参考，到**上下文指针**背后的外部参考的阶梯。**渐进式披露**是沿着那个阶梯向下移动，让顶层保持可读。
- **修剪**——单一真相来源、相关性，以及逐句应用的无操作测试，针对**沉淀**和**蔓延**。
- **失败模式**——**过早完成**、**重复**、**沉淀**、**蔓延**、**无操作**——用于诊断行为异常的 skill。

## 它在哪里

这是一个随时可用的独立参考——你在构建其余集合时咨询的元 skill，而非链条中的一步。它的天然邻居是你维护的任何路由器，因为路由器是用户调用 skills 堆积的认知负荷的直接解药；当你不确定哪个 skill 或流程适合某项任务时，[ask-matt](https://aihero.dev/skills-ask-matt) 在整个集合上为你路由。
